# Connectivity: Wi-Fi, Bluetooth, remote services, files/shares/backup, Syncthing

## Wi-Fi (§24)
Smartphone-like, controller-first. Top bar distinguishes off / on-not-connected / connecting / connected; state and SSID live, event-driven. Capabilities: scan, connect, disconnect, saved networks, forget, hidden SSID, autoreconnect, per-network IPv4: Automatic/DHCP (runtime config shown read-only: address, derived mask/prefix, gateway, DNS, other useful values) or Manual (address + prefix or netmask, gateway, DNS; gateway may be empty for local networks without a default route — never invent one). Normal UX never shows kernel/driver/wpa_supplicant/udhcpc details. Password entry: complete classic QWERTY full-width bottom sheet, controller-first, physical keyboard support, pages for normal characters. Known Wi-Fi defects: open-items.md.
- WPS push-button (added 2026-10-07 on explicit user request during Alpha→RC): `BR2_PACKAGE_WPA_SUPPLICANT_WPS=y` (selected by `nuubos-wifi`). Contract: `StartWps(ssid)` (`wps_pbc` on the strongest BSSID of that SSID advertising `[WPS`, otherwise any AP in PBC mode; sets `update_config 1` at runtime because older STATE files carry `update_config=0`, so wpa_supplicant persists the credentials itself), `CancelWps()`, `GetWpsActive()`, signal `WpsStateChanged(b)`, failures as `OperationFailed("wps", timeout|overlap|failed)` — stable codes, localized by the UI. Overlap → wifid sends `wps_cancel` (wpa_supplicant would wait the 2 min walk time). Success → `chmod 0600` of the conf (wpa_supplicant writes 0660) + networks snapshot. Connect/Disconnect/SetEnabled cancel a running session; a drop caused by WPS is not reported as `wifi.lost`. While WPS runs wpa_supplicant disables the other networks; on cancel/timeout it reconnects to the previous one (a `wifi.connected` toast follows).
- Clean STATE (first boot, after a settings reset) has no `/state/network/wpa_supplicant.conf`: `S44nuubos-wifid` and wifid `ensure_wpa_running()` write the base config (`ctrl_interface`, `country=IT`, `update_config=1`, no networks) and start wpa_supplicant anyway. Before 2026-10-07 they skipped it, so the OOB scan failed with "wpa_supplicant is unavailable". wpa_supplicant must be up at boot: the `wpa_cli -a` listeners (S44, S48) attach only then.
- wpa events: wifid owns a wpa_supplicant control-interface monitor (datagram socket `/run/nuubos/wifid-wpa-<pid>` → `/var/run/wpa_supplicant/wlan0`, `ATTACH`), polled in its main loop and processed in arrival order. Not `wpa_cli -a`: its action mode forwards only CONNECTED/DISCONNECTED/WPS-*, never `CTRL-EVENT-SCAN-RESULTS`/`SCAN-FAILED`/`SSID-TEMP-DISABLED` (until 2026-10-07 scans never completed: spinner forever, no session rescans, no list). Reattach happens in `ensure_wpa_running()` (after `CTRL-EVENT-TERMINATING` or a wpa_supplicant restart); `Scan` fails if no monitor is attached. `scan` → `FAIL-BUSY` (wpa_supplicant already scanning) counts as started. Scan results wpa_supplicant collects on its own refresh the list but do not end `ScanStateChanged`. `nuubos-wifi-event` and the S44 listener are gone; S48 keeps its own `wpa_cli -a` listener.
- DHCP (2026-10-08, user report "after a reboot DHCP fails, a disconnect/reconnect fixes it"): wifid used a one-shot `udhcpc -q -n -t 5 -T 3` spawned by a grandchild, so a failed first exchange after boot left no address for good (and no lease renewal, no log). Now wifid itself runs one persistent `udhcpc -f -t 5 -T 3 -A 10` per association (retries every 10 s until a lease, renews it; log `/run/nuubos/wifi-dhcp.log`), kept across same-SSID reconnects (rekey: a restart would deconfigure the address), stopped when the SSID changes or Wi-Fi is off, and on exit; a manual profile stops it first. The original boot failure was not reproduced (no logs existed).
- DHCP at boot, root cause (2026-10-12, user report "every boot needs a manual reconnect", reproduced with a debug wifid): the address was set up only when the main loop's own refresh saw the state change to connected; at boot a `GetSnapshot` (UI/statusd) or the scan-results path refreshed `current` first, so the loop's refresh after `CTRL-EVENT-CONNECTED` saw no change and never started udhcpc. Now `ensure_ip_profile()` runs at startup and after every loop iteration: connected + an SSID whose IP profile was not applied for this association (`ip_ssid`) → `spawn_apply_ip_profile()` once; any non-connected state clears it. Verified on the CubeXX: two reboots, lease at ~20 s, no reconnect.
- Live network page: the `StateChanged` snapshot carries the IPv4 address (udhcpc's hook and, since 2026-10-08, the manual-profile child signal wifid with SIGUSR1), so Home refetches only the runtime lease values (`fetch_wifi_ip_configuration(.., runtime_only)`) on every snapshot while settings-view 4 is open: connect/disconnect/renew show the new address without leaving the page, edits in progress are kept.
- Connect page (view 2): while a session scan runs and networks are already listed (e.g. the current one), the status line says "Searching for nearby networks…" (before, the indicator showed only on an empty list, so a scan while connected looked like it never started). Checked 2026-10-08 on RG40XX-V: rtw88 (RTL8821CS) scans while associated and `GetNetworks` returns the other BSSs (5 networks).
- UI: network page (settings-view 4) row 1 "Connect with WPS" / "Cancel WPS" (enabled for non-current personal networks: not Open/Enterprise/WEP); rows after it shifted by one (`DETAIL_ROWS` 10). The instruction notice stays while WPS runs (ScanStateChanged does not clear it). Strings 705–711.
- Replacing `wpa_supplicant` on the dev target over Wi-Fi: stage, then a detached `setsid sh -c` doing S44nuubos-wifid stop → `killall wpa_supplicant` → `mv` → start (the SSH link drops for a few seconds); restart `S48nuubos-status` afterwards (own `wpa_cli -a` listener); wifid reattaches by itself.

- Sleep (2026-10-11): the RTL8821CS is unpowered during system sleep. Kernel `patches/linux/h700/0104-wifi-rtw88-sdio-power-off-card-in-system-suspend.patch`: `rtw_sdio_suspend` no longer requests `MMC_PM_KEEP_POWER` (it used to, so the card stayed on 3.3 V `vcc-wifi`/CLDO4 and suspend would have failed without the DT `keep-power-in-suspend`, which now only allows it); it releases the SDIO IRQ and disables the function, the MMC core powers the card off, and on resume the driver re-enables the function, block size 512 and the IRQ before mac80211 restarts the device (firmware reloaded). Bluetooth on the same chip was already off: the DT `realtek,rtl8821cs-bt` falls back to the `rtl8723bs-bt` data (`H5_INFO_WAKEUP_DISABLE`: enable GPIO low in suspend, reprobe on resume). Hardware-confirmed on the CubeXX in deep sleep: 5/5 cycles, Wi-Fi associated again 5 s after resume, BT reinitialised. rtw88 is a module: deploy `rtw88_sdio.ko`, reboot.

- Regulatory domain (2026-10-11, legal audit): no fixed `country=IT` any more. regionald derives the ISO country from the user's time zone (`/usr/share/zoneinfo/zone.tab`; UTC or an unknown zone = `00`, the world domain, legal everywhere), applies it with `iw reg set` at start and on every time zone change and publishes `wifi_country=` in its STATUS. wifid no longer writes or keeps `country=` in `wpa_supplicant.conf` (it would override the region when wpa_supplicant starts) and `S44nuubos-wifid` strips it from existing configs. Signed `regulatory.db` from wireless-regdb (`CONFIG_CFG80211_REQUIRE_SIGNED_REGDB`). To verify on hardware: `iw reg get` after boot and after changing the time zone.

## Remote Services, credential, Web admin (§37.19, EPIC-037/038/039)
- Package `nuubos-remote`: `/usr/sbin/nuubos-remotectl start|stop|status|set ssh|smb|web 0|1|credential show|regenerate`. The overlay `S50dropbear` replaces Buildroot's script and calls `nuubos-remotectl start|stop`. Config `/state/config/remote.conf` (`SSH= SMB= WEB=`, all 0 by default).
- Device credential: random `xxxx-xxxx-xxxx` per device in `/state/remote/credential` (0600), user `root`, for SSH, SMB (`/state/remote/ksmbd/ksmbdpwd.db`, kernel ksmbd + ksmbd-tools, config `/etc/nuubos/ksmbd.conf`, one share `nuubOS` = `/userdata`) and Web administration (nuubos-admind reads the credential at every sign-in). Regenerate rewrites hash/SMB db, restarts a running SMB and ends every web session (sessions remember the credential they were opened with).
- SSH (changed 2026-10-07 on explicit user decision): root signs in with the device credential only. `apply_password` hashes it (busybox `mkpasswd -m sha512 -P 0`) into `/state/remote/root.hash` and writes root's `/etc/shadow` field; every `start` re-applies it because image updates replace the rootfs `/etc/shadow`. Dropbear runs without `-s -g` and is built with `DROPBEAR_SVR_PUBKEY_AUTH 0` (`board/nuubos/common/dropbear-localoptions.h` via `BR2_PACKAGE_DROPBEAR_LOCALOPTIONS_FILE`; that hook runs at extract, so a change needs `dropbear-dirclean`): `authorized_keys` has no effect. Serial console ttyS0 stays password-free: `BR2_TARGET_GENERIC_GETTY_OPTIONS="-n -l /usr/libexec/nuubos-console-login"` (`login -f root`, physical access only). UI hint string 601. SFTP sessions start in `/userdata` (user request 2026-10-10): `/usr/libexec/sftp-server` is a wrapper (nuubos-sftp-server) running OpenSSH's `sftp-server.bin -d /userdata`.
- Kernel: `CONFIG_SMB_SERVER=m` in `board/nuubos/platform/h700/linux.config`; only adds `ksmbd.ko` (built-in code unchanged, so `/boot/Image` need not be replaced). Deployed with `modules.*` on 2026-10-07.
- ksmbd-tools is built with Kerberos (libkrb5 is in the image for Steam Link): without a keytab upstream `ksmbd.mountd` aborted its worker and the manager restarted it every second (kernel "Reconnect to a new user space daemon", CPU/battery). `patches/packages/ksmbd-tools/0001` disables the Kerberos mechanisms instead (2026-10-08, hardware-confirmed: the worker stays up; an SMB password login still to be retested). Check: `dmesg | grep -c Reconnect` must stay constant.
- Web administration 0.2 (rewritten 2026-10-10 on explicit user request during Alpha→RC: same UX as nuubUI, the user's Mood, a full control centre, sign-in page, HTTPS):
  - lighttpd 1.4.84 with mod_openssl (`BR2_PACKAGE_LIGHTTPD_OPENSSL`, selected by nuubos-remote; `lighttpd-reconfigure` after the change), `/etc/nuubos/web/lighttpd.conf`: HTTPS on 443 only, port 80 = 308 redirect, runs as `www-data` (reads the key as root at start; `/run/nuubos/web.log` is chowned first because lighttpd opens it after dropping privileges), static app `/usr/share/nuubos/web`, Cantarell from `/usr/share/fonts/cantarell` (`/fonts/`), `/api/` proxied to `nuubos-admind` on `/run/nuubos/admin.sock` (0600, owner www-data), CSP `'self'` only (no inline styles: set CSS variables from JS), `stream-request-body 2` (backpressure, no temp files: `/userdata` is exFAT, chown impossible). lighttpd is built WITHOUT pcre: no `=~`/`!~` conditions (use `=^` + `else`).
  - TLS: per-device self-signed ECDSA P-256 certificate (`nuubos-web-cert`, C on libcrypto; CN = hostname, SAN hostname, hostname.local, nuubos.local; 10 years) created by `nuubos-remotectl` at the first web start: `/state/remote/web-key.pem`, `web-cert.pem`, SHA-256 fingerprint in `web-cert.sha256` (`status` prints `web_fingerprint=`). Kept across restarts (browsers remember the exception).
  - `nuubos-admind` (Rust, `package/nuubos/nuubos-remote/src/admind`, crates zbus/serde_json only, unit tests `cargo test`): sign-in `POST /api/login` (user root + credential, constant-time compare, lockout per client address after 4 failures, 15 s doubling up to 15 min), session cookie `nuubos_session` (HttpOnly, Secure, SameSite=Strict; in memory only; idle 4 h, max 7 days). Writes need header `X-NuubOS: 1` + same Origin. `GET /api/get?t=TOPIC` = a service reply as JSON (key=value → object; tab rows → field lists; repeated keys → lists), `POST /api/do {op,...}` = one product command with checked arguments (table in `api.rs`), `GET /api/events` = SSE: while a page listens, watchers SUBSCRIBE to systemd/usersd/localizationd/regionald/libraryd/jobd/emud/statusd and follow the D-Bus signals of Audio/Wifi/Bluetooth/Controllers/Lighting/Rumble, sending `{"t": topic}`; a watcher stops at the first notification with no listener (no page open = no subscriptions; audiod's few socket subscriber slots are left to the QM). Files: `PUT /api/upload?dir&name[&replace][&mkdirs][&after=scan|mood|bios]` (hidden `.part` + rename, no overwrite unless replace, free-space check), `GET /api/download`, `GET /api/img` (realpath inside `/userdata`, `/media`, `/run/nuubos/shares`, plus system artwork for images; dot names refused). Actions that end the daemon or the system (Web off, update install, factory reset) answer first and run detached.
  - Web app (`www/`: index.html, app.css, app.js = shell/toolkit, pages.js = pages, i18n.js = web-only strings in 7 languages; console strings come from the device catalogs by index via `/api/i18n`, language = the console's active user). Same grammar as Settings: rail (Manage: Overview, Library, Files, BIOS Files | Settings: the seven console categories, same sections/rows/strings), tonal rows, M3 switches, QM sliders, choice sheets, armed double-press, notification cards; spatial keyboard navigation (arrows, Enter, Esc), mouse/touch, phone layout below 860 px. Mood tokens → CSS variables, M3 roles derived like `ui/theme.slint`. Uploads take several files and whole folders at once (drag and drop or picker), one progress card. Icons: the nuubUI Font Awesome set + 14 more FA 6.7.2 icons (`www/icons/ATTRIBUTION.txt`), used as CSS masks.
  - A Mood chosen on the web reaches nuubUI at once: `nuubos-themectl select` writes `mood` to `/run/nuubos/ui-control` (opened read-write, never blocks); Home's lifecycle listener calls `themes::apply_active`.
  - Not covered on the web (need the console's buttons): controller remapping, input tester. Not done: launching a game from the web.
  - Host tests: `sh package/nuubos/nuubos-remote/tests/remote.sh`, `cargo test` in `package/nuubos/nuubos-remote/src`. Hardware: verified 2026-10-10 on RG40XX-V with curl (redirect, sign-in/CSRF/origin, every topic, actions, multi-file upload, download, SSE) and headless Firefox screenshots through a cookie-injecting proxy (no drivers on the host).
- UI: Settings → Connectivity, section SERVICES (user requests 2026-10-08: moved from System, then the sub-pages removed): rows from 6 = SSH (detail `root@<address>`), File Sharing (SMB) and Web Administration toggles with address hints (`https://<address>`), Password (masked; confirm shows it, hidden again when Connectivity is entered/previewed), Regenerate Password (armed). Syncthing moved to Settings → Gaming on 2026-10-12 (user request). Built by `gameui.rs` (`service_rows`, `refresh_services` = `nuubos-remotectl status`, `services_confirm`); the former Remote Services (57) and Online Services (64) pages no longer exist. Together they are the EPIC-055 inventory of optional services (Software Update in System, ScreenScraper/RA in Gaming).
## Files, removable media, network shares, backup (§37.20, EPIC-024/031/032/035/036)
- Package `nuubos-files`: `nuubos-filesctl roots|list|info|mkdir|rename|delete|copy|move` (C; allowlist `/userdata`, `/media/<volume>`, `/run/nuubos/shares/<name>` after realpath; `.nuubos-upload`, `lost+found`, `.stage.*` and dot-names hidden/refused; copy never overwrites (" (2)"), `.part` + rename, space check, progress as a job worker), job types `file-copy`, `file-move` (no cancel).
- `nuubos-mediactl list|eject NAME|hotplug add|remove DEV`: udev rule `72-nuubos-removable.rules` mounts USB filesystems (vfat/exfat/ext*) at `/media/<label>` `nodev,nosuid,noexec`; pulled drives are lazily unmounted; notifications `media.connected|removed`. USB volumes are never ROM locations.
- `nuubos-sharesctl list|add NAME //HOST/SHARE [USER] (password stdin)|mount|umount|remove`: busybox `mount -t cifs` (kernel CIFS=m), credentials `/state/shares/<name>.conf` 0600, mount bounded to 15 s, mounted at `/run/nuubos/shares/<name>`; passwords with commas are refused (kernel option string).
- Backup & Restore (EPIC-035): one console backup, `nuubos-sd2-backup`, platform.md "Console backup" (the per-profile `nuubos-backupctl` tar was removed 2026-10-12 on user request; a single profile is restored from the console backup). Web admin: System → Storage, BACKUP section (Automatic Backup, Destination, Back Up Now, Backup Content; `storage.backup.dest`); restores run on the console only.
- UI: Home → Applications → Files (`files.app`, icon = XMB Monochrome `folder.png`, CC BY 4.0, attribution in the package) opens the Files shell (`filesui.rs`, settings-view 58 browser: locations → folders; Paste Here, New Folder, dropdown Open/Copy/Move/Rename/Delete; 60 Network Shares with Add Share keyboard flow), Settings → System → Storage → Removable Media (61, armed eject; lists the games card as "SD2", its eject goes to nuubos-storagectl; `sd2` is a reserved volume name), System rows 4 Backup (62) and 5 Recovery (28) (storageui.rs rows). Keyboard purposes 16–21. The Details shell is shared (`details-shell-title`).
## Syncthing (§37.26, EPIC-034)
Redesigned 2026-10-12 on explicit user request during Alpha→RC ("ripensa completamente la gestione di Syncthing" + a guided full-screen setup).
- `package/thirdparty/syncthing` (2.1.6, MPL-2.0, golang-package, tags `noupgrade noassets`: no embedded web GUI, ~31 MB binary). Package `nuubos-sync` 0.2.0.
- `nuubos-syncd` (`S49nuubos-syncd`, C, cjson/libcurl/pthread) OWNS the capability: runs Syncthing only for the active user and only if enabled, applies the policy, follows Syncthing's events and publishes a snapshot. Per user in `/userdata/users/<id>/appdata/syncthing/`: Syncthing's home + `nuubos.conf` (`ENABLED APIKEY INTERNET RELAYS FOLDERS=saves,states,screenshots,library,history`; no FOLDERS line = saves only). FOLDERS/INTERNET/RELAYS live in nuubos.conf, so they can be set before Syncthing runs (the guide sets them while it starts).
  - Process: `syncthing serve` with `STMONITORED=yes` (Syncthing 2 starts a ~44 MB monitor process even with `--no-restart`; measured on the CubeXX: one process ~53 MB instead of two ~95 MB), nice 10, `STNODEFAULTFOLDER`, GUI/REST only on `/run/nuubos/syncthing/gui.sock` (dir 0700, no network GUI). Ready = inotify IN_CREATE of `gui.sock` (no polling). A crash is not restarted (`failed=1` until ENABLE or a user switch).
  - Policy at every start: own device name "<profile USER_NAME> · <model without "Anbernic ">" (all consoles used to be called "nuubos", the hostname); options `globalAnnounceEnabled/natEnabled` = INTERNET, `relaysEnabled` = INTERNET && RELAYS (split on user request 2026-10-12: discovery/NAT/STUN only find the devices, data stays direct; relays carry the encrypted data, a separate opt-in; both off by default), `stunKeepaliveStartS` 0 when local-only, `localAnnounceEnabled` on, `crashReportingEnabled` false (Syncthing's default is true), `urAccepted -1`; folders (user request 2026-10-12: also covers/metadata and play activity, each a switch): kind saves → `nuubos-saves` (`users/<id>/saves`), states → `nuubos-states`, screenshots → `nuubos-screenshots`, library → `nuubos-covers` + `nuubos-metadata` (`/userdata/library/covers|metadata`: the console's store, shared by its profiles, one file per game; when one of them goes syncing → idle syncd sends `SCAN` to libraryd so the metadata index and covers refresh), history → `nuubos-history` (`users/<id>/library/consoles`, play activity, see home-users-oob.md); all sendreceive, `ignorePerms` (exFAT), shared with every configured device; saves with trash-can versioning 30 days in `.stversions`). Folder off = removed from Syncthing, files stay. Same ids everywhere, so two consoles meet in the same folder. ROMs never synced, conflicts stay as `.sync-conflict` copies.
  - Events: a thread long-polls `/rest/events?since=&timeout=300&events=DeviceConnected,DeviceDisconnected,DeviceDiscovered,DevicePaused,DeviceResumed,PendingDevicesChanged,ConfigSaved,StateChanged,FolderCompletion,FolderErrors` (a filtered subscription only buffers from its first request: the initial folder states come from `/rest/db/status` once at ready). Any event → snapshot rebuilt from REST (`config/devices`, `system/connections`, `cluster/pending/devices`, `system/discovery`) + folder states/completions from the events; subscribers get it only when it changed.
  - Socket `/run/nuubos/syncd.sock` (0660): `STATUS`, `SUBSCRIBE`, `ENABLE`, `DISABLE`, `FOLDER <kind> 0|1`, `INTERNET 0|1`, `RELAYS 0|1`, `ADD <id> [<name>]` (accept a request or add a nearby device; re-shares the folders), `IGNORE <id>` (into `remoteIgnoredDevices` via GET/PUT `/rest/config` — Syncthing 2 has no dedicated endpoint — then the pending entry is deleted), `REMOVE <id>`; replies `OK` / `ERR no-user|not-running|device|syncthing|storage|value|unknown`. Snapshot: `enabled running ready failed internet relays device_id device_name`, `folder=<kind>\t<on>\t<state>`, `device=<id>\t<name>\t<connected>\t<completion|-1>\t<address>`, `pending=<id>\t<name>\t<address>`, `nearby=<id>\t<address>` (local discovery cache minus self/configured/pending; Syncthing caches EVERY device announcing on the LAN, `lib/discover/local.go`), `end=1`.
  - Stale requests: Syncthing keeps a pending device in its database forever (a device that tried once came back at every start with a toast: found 2026-10-12 after a test peer on the same console, 127.0.0.1, name "nuubos"). A requester retries about every minute and each refused attempt renews its `time`, so syncd drops (DELETE `/rest/cluster/pending/devices?device=`) and hides requests older than 5 min whenever it builds a snapshot.
  - Live Notification `sync.request` (`name=`, id `sync.<7 chars>`) once per syncd run when a device asks to connect; dismissed when accepted/ignored/gone. Rendered by the Quick Menu (string 1083).
  - `nuubos-syncctl status|enable|disable|folder KIND on|off|internet on|off|relays on|off|add DEV [NAME]|accept DEV [NAME]|ignore DEV|remove DEV` is a thin client of the socket (no curl/cjson).
- Same games? Saves are matched by RetroArch through the ROM file name: a console without a game simply keeps its save file (a few KB); the same game under different file names does not share saves (the guide says so, string 1093). Per user: own Syncthing identity, devices and folders; only the active profile runs.
- UI (`syncui.rs`, nuubui-home): one permanent SUBSCRIBE listener (reconnect pause 0.5 s doubling to 30 s); the snapshot re-renders page 66, Settings → Gaming and the guide.
