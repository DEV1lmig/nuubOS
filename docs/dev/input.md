# Input / controllers

## Product rules (§26)
Controller-first with logical actions, never controller-brand semantics. Required before the relevant final milestone: Controller Mapping, Input Tester, RGB Lighting where supported. Mapping reset belongs to Reset System Settings. Default face roles (2026-10-07): `menu_confirm` = BTN_SOUTH (bottom), `menu_back` = BTN_EAST (right), in controllersd defaults, inputd defaults/`input-bindings.conf`, tester and labels. Games are unaffected: the game gamepad emits `menu_confirm`→BTN_SOUTH and `menu_back`→BTN_EAST, so physical east stays RetroArch A. Extra logical actions: `face_north` (Favorite on Home, home-users-oob.md), `face_west` (Game Details, emulation.md §37.18). Game gamepads/hotkeys: emulation.md §37.13. Physical keyboard: ui.md §37.24.

## Controller mapping (§37.3)
- Controller mapping (owner `nuubos-controllersd`, D-Bus `org.nuubOS.Controllers1`): 17 button controls + `left_x/left_y/right_x/right_y`; each bound to one source `key:CODE`, `abs:CODE:+|-` (half axis; on a stick axis = normal/inverted), `abs:CODE:>|<` (full trigger travel from min/max) or `none`. Defaults are derived from the device's evdev capabilities (D-pad keys or hat, L2/R2 keys/Z-RZ/BRAKE-GAS, right stick RX/RY or Z/RZ); `/state/users/<u>/controllers/<hex-id>.conf` stores only differences (legacy `action=305` still read). Capture: `BeginRemap` → inputd sends `RAWBASE`/`RAWREADY` baselines (normalized -100..100) → stick vs trigger is told apart by rest position; 5 s timeout (`RemapCancelled`), any button cancels a stick capture; a source already in use is swapped (same kind) or unassigned (other kind). inputd only consumes the navigation actions + `left_x/left_y` (stick navigation) and parses the same format. Input Tester `InputEvent` carries the resolved logical control and value (buttons 0..100, sticks -100..100).
- Input Tester UI (settings-view 14, user request 2026-10-08): `ControllerTesterVisual` in home.slint draws a brand-free pad on a 360x200 grid scaled by `u` (top-aligned, M3 Theme tokens; triggers fill with analog travel, stick knobs move with the logical value). Below it the last-input chip and the exit combo `H + START` (i18n 740): controllersd ends the tester when Hotkey and Start are held together (`TesterExitRequested`), because the tested controller's Back is captured. Navigate/Select hints are hidden on that page. Headless: ui-shot scene `tester`.
## Select and face actions (2026-10-10)
- New logical action `select` (default BTN_SELECT 314 in inputd defaults and input-bindings.conf, controller mappings by the `select` control name), routed like the navigation actions: Home opens Find a Game.
- Home: North = Game Details (was West), on a collection Manage; West unused on Home. System keyboard: West = delete the last character.
- UI actions `tab_prev`/`tab_next` (2026-10-13): L2/R2 (`BTN_TL2`/`BTN_TR2`, 312/313; checked in the CubeXX gpio-keys capabilities) in `default_bindings` and `input-bindings.conf`, routed like the other navigation actions (Home while Settings/an app owns input, the Quick Menu while it is open). Used by the Media app's Music/Video sections.
- UI actions `page_prev`/`page_next` (2026-10-14): L1/R1 (`BTN_TL`/`BTN_TR`, 310/311), same routing; Home uses a double press for previous/next track while music plays (streaming-media.md). Not repeated when held.
- Analog stick poll rate (battery audit 2026-10-14): nuubos-inputd writes `/sys/class/input/eventN/device/poll` of `adc-joystick` devices: 4 ms (the device-tree rate) while a game owns the controllers, 16 ms in menus (stick navigation), 100 ms while `/run/nuubos/screen-off` exists (inotify on /run/nuubos); written only when it differs, logged as `stick poll eventN M ms`. Kernel `0106` raises the poller maximum to 100 ms (before it equalled the device-tree value: EINVAL). H5 accepts 4/16/100 and checks `max` = 100.
