# Emulation (RetroArch hybrid) and game UX

## Frozen direction (§18)
Hybrid model: RetroArch/libretro is the only backend (standalone emulators out of scope, EPIC-014 removed 2026-10-07). nuubOS exposes common recurring actions through native controller-first UI/Product APIs; `RetroArch Advanced` opens RetroArch's native menu for power users. Never reimplement the RetroArch configuration UI nor duplicate it in Settings → Gaming.
- §18.1 With a game running, the GAME section is at the TOP of the Quick Menu, before system controls.
- §18.2 Hotkeys/chords at least for Save State, Load State, change Save Slot, Fast Forward; `M` is the modifier layer while `M` alone opens the Quick Menu. Hotkeys go through the SAME Emulation Service/Product API as menu actions (no second direct RetroArch-control path in the input layer); a global OSD/notification confirms.

## RetroArch backend (§37.13, EPIC-013/019)
- Packages: `package/libretro/` — `retroarch` 1.22.2 (Wayland + EGL/GLES3 on Panfrost, udev joypads, ALSA + PipeWire, stdin commands; no X11/SDL/Vulkan/FFmpeg/KMS/slang), `retroarch-assets` (Ozone subset), `libretro-core-info`, 15 cores (matrix, licences and the non-commercial decision in `package/libretro/README.md`). `BR2_PACKAGE_NUUBOS_EMULATION` selects them all. Core build quirks live in `libretro.mk` (GCC 15 flags), `libretro-mgba` (CMake), `libretro-picodrive` (`-U_LARGEFILE64_SOURCE`). RetroArch patches: `0001` stdin `SAVE_STATE_SLOT n` / `SET_PAUSED 0|1` / `LOAD_STATE_SLOT n` with `OK|FAILED` newline-terminated replies (hotkey commands are edge-triggered bits that collapse within one frame and report nothing); `0002` Wayland EGL config for GLES2 contexts in a GLES3-only build (without it RetroArch segfaults at start).
- Service `nuubos-emud` (package `nuubos-emulation`, `S49nuubos-emud`, socket `/run/nuubos/emud.sock`, log `/run/nuubos/emud.log`, RetroArch stderr in `/run/nuubos/retroarch.log`, CLI `nuubos-emuctl status|watch|launch ID|pause|resume|save|load|slot N|+1|-1|reset|fast-forward|advanced|quit|pre-power ACTION|storage-lost MOUNT`). `STORAGE_LOST\t<mount>` (nuubos-storagectl, games card pulled out): a session whose ROM is under it takes the automatic state (not in hardcore), quits like before a power off and posts `game.storage_lost`. Every session end that is not a power action runs `nuubos-sd2-backup trigger session-end`. Protocol like libraryd: `STATUS`/`SUBSCRIBE` snapshot (`state=idle|running|exiting`, `game=`, `system=`, `core=`, `paused=`, `slot=`, `fast_forward=`, `state_busy=`, `end=1`); `LAUNCH\t<game>` replies `OK` or `ERR busy|no-user|game|unavailable|no-core|library|storage|spawn`. One session at a time; idle = poll without timeout (timers only while a save/quit is pending); child exit via SIGCHLD self-pipe.
- Launch: libraryd `RESOLVE` → `cores.conf` (`/usr/share/nuubos/emulation/cores.conf`, `system|core,...`: first bundled core in `/usr/lib/libretro`, else first downloaded one in `/userdata/retroarch/cores`) → per-user dirs → `retroarch --config <user cfg> --appendconfig /run/nuubos/emulation/session.cfg -L core content` with stdin/stdout pipes, `setsid`, env `XDG_RUNTIME_DIR=/run/nuubos/wayland-runtime`, `HOME=<ra dir>`, `XDG_CONFIG_HOME=<user>/appdata`. libraryd `SESSION_BEGIN/END` around the process (Last/Time Played).
- Configuration layers: per-user `/userdata/users/<id>/appdata/retroarch/retroarch.cfg` seeded once from `/usr/share/nuubos/emulation/retroarch.cfg` (H700 defaults: vsync, no threaded video, pixel perfect presentation (below), ALSA 64 ms, SRAM flush 10 s, no rewind/run-ahead, analog→D-pad, Ozone, Reboot/Shut Down hidden, aarch64 buildbot core URL), `retroarch-core-options.cfg` seeded from the core option defaults (global core options), user edits in RetroArch Advanced kept (`config_save_on_exit`). The session config (written every launch) enforces paths, drivers, ports, stdin commands (UDP network commands never), `quit_on_close_content`, OK = RetroPad A, language from the user's nuubOS language. Saves `/userdata/users/<id>/saves/<system>`, states `.../states/<system>` (`<rom name>.state[N]`, automatic slot `.state.auto`), screenshots `.../screenshots`, BIOS `/userdata/bios` (shared), cache `/userdata/cache/retroarch`.
- Controllers: games only see `nuubOS Gamepad` uinput devices from nuubos-inputd (one per player, product id = player, vendor 0, `/devices/virtual/input`; RetroArch reserves port N for `0000:000N`; autoconfig `/usr/share/retroarch/autoconfig/udev/nuubOS Gamepad.cfg`: SOUTH..THUMBR = buttons 0..11, D-pad hat 0, axes X/Y/RX/RY 0..3). controllersd pushes the resolved table on every device/user/mapping/deadzone/assignment change (`PADMAP BEGIN`, `PADMAP <id> player=N left_deadzone= right_deadzone= <control>=<source>...`, `PADMAP END`). emud sends `GAMEPADS ON` and keeps that connection: gamepads go off when it closes. While on, inputd grabs every controller; game controls go to the player's game gamepad (nothing while the Quick Menu is open, everything released when it opens), no nuubUI navigation leaks to Home. udev rule `71-nuubos-game-gamepads.rules` clears `ID_INPUT_JOYSTICK` (and sets `LIBINPUT_IGNORE_DEVICE`) on physical controllers so RetroArch/SDL never take them as extra players.
- Hotkeys (CLAUDE §18.2, user request 2026-10-08): in a game the Quick Menu button (Hotkey) is a modifier; alone it opens the Quick Menu on release. Defaults H+R1 save state, H+L1 load state, H+Up/Down slot +/-, H+North fast-forward, H+Start quit (auto-saves), H+L2 screenshot; remappable per user in Settings → Gaming → Game Hotkeys (page 55, dropdown of the 16 logical controls). emud owns them (`hotkey_<action>` in the user's emulation settings) and sends `HOTKEYS <action>=<control> ...` to inputd after `GAMEPADS ON` (and on every change/reconnect); inputd falls back to its defaults otherwise. Chords also work for controls bound to an axis (hat D-pad, analog triggers: same 50/30 % thresholds, edge-detected while the modifier is held). inputd writes `HOTKEY <action>` on emud's gamepads connection; emud runs the same code as the Quick Menu commands.
- User emulation settings (Settings → Gaming, user request 2026-10-08): emud `SETTINGS` / `SET <key> <value>`, stored in `/userdata/users/<id>/appdata/nuubos-emulation/settings.conf`: `boot_screens` (0; rewrites the boot keys of the user's core options at launch: `pcsx_rearmed_show_bios_bootlogo`, `mgba_skip_bios`, `gambatte_gb_bootloader`, `genesis_plus_gx_bios`, `melonds_boot_directly`), `slots` (10, 1-99), `slot_rotation` (1), `bezels` (1, user decision 2026-10-15), `crt` (1, user request 2026-10-09: the light CRT look is on by default where it applies), `overlay` (0), `overlay_items` (`fps,cpu,ram,temp,battery,clock`; also `gpu`, `power`; `ram` = systemd PERF `mem.used_mib`, battery shown as `BAT n%`), `hotkey_*`. Hotkeys and overlay apply live to a running game of that user, the rest at the next launch. Gaming page rows: RetroAchievements, Console Boot Screens, Save State Slots, Rotate Save Slots, Game Hotkeys, Performance Overlay (page 56), Bezels, CRT Effect, then LIBRARY from `gaming-split`.
- Save states (EPIC-019, user request 2026-10-08): without slot rotation RetroArch writes `.state.auto` whenever the game closes (`savestate_auto_save` in the session config). With slot rotation (user request 2026-10-11, the default) the automatic save follows the rotation: `savestate_auto_save` is off and emud saves quietly into `save_target()` before asking RetroArch to quit (`request_quit`: `quit_requested`/`quit_saved`, once; a failed or timed-out save still quits) and on `PRE_POWER` (sleep: the game keeps running with that slot selected; restart/poweroff: the quit does not save again). Gap: Close Content from RetroArch Advanced's own menu bypasses emud, so with rotation nothing is saved then. `LAUNCH <game> [resume|new|slot:N]`: resume (default, Home short press, Details Play) starts from the most recent state (auto or numbered, by mtime: auto → `savestate_auto_load`, slot → `--entryslot N`), new from the beginning, `slot:N` from that slot (`-1` = auto). Rotation: a save goes to the selected slot if empty, else to the next one (wrapping to 0); the saved slot becomes the selected one (Load State loads the latest save). At launch the selected slot is the start slot or the most recent numbered one. `STATES [game]` lists `slots=N` + `state=<slot>\t<mtime>\t<HH:MM>`. Home: holding Confirm 600 ms on a game card opens the Start Game bottom sheet (redesign 2026-10-11, user: the page-57 Settings shell "fa cagare"): a Home modal rising from the action bar (`start-sheet-*` in home.slint, `gameui::open_start_sheet`/`start_sheet_action`, opened only once emud STATES answered): game header (cover, title, system), row 0 Start from the Beginning (focused), then SAVE STATES newest first (slot number tile or a clock for the automatic save, "Saved <day> • hh:mm", a Latest chip on the newest; "No saved states yet" when none). Confirm launches `new` / `slot:N`; Back closes. Page 57 no longer exists. ui-shot scenes `start_game`, `start_game_empty`. Home now gets `menu_confirm released` from inputd and launches on release.
- Quick Menu over a game: GAME section first (Resume, Save State, Load State, State Slot (a dropdown only, user request 2026-10-08: confirm opens every slot with its save time or Empty, left/right do nothing), Restart Game, RetroArch Advanced, Screenshot, Performance Overlay (row 28, switch = the user's `overlay` setting via emud `SET`, applied live), Quit Game; Load/Restart/Quit need a second press); QM dropdowns open above their row when the screen ends first; opening pauses (`PAUSE`), every close resumes (`RESUME`) except Quit and RetroArch Advanced. Switch User is hidden over a game. The power key opens the Power OSD (quick-menu-notify.md) over the game, which waits paused underneath.
- Sleep with a game running (fixed 2026-10-08): `panfrost_device_suspend` returned -EBUSY whenever a job was still on the GPU at freeze time (a game always has one), aborting s2idle ("PM: Some devices failed to suspend"); Home alone never hit it because it is idle. Kernel patch `0029-drm-panfrost-wait-for-jobs-before-system-suspend.patch` waits up to 1 s for the queued jobs (user space is already frozen). Hardware-confirmed: N64 running, s2idle entered, auto state written, wake by a key.
- Outcomes are notifications (`game.state.saved|loaded|empty|failed`, `game.slot`, `game.fastforward`, `game.failed reason=start|crash`); state saves are confirmed only when the file is closed (inotify `IN_CLOSE_WRITE`/`IN_MOVED_TO` on the state dir, 10 s timeout).
- Lifecycle: `/usr/lib/nuubos/lifecycle-hooks/pre-power.d/50-emulation` → `nuubos-emuctl pre-power <action>`: saves the automatic state slot before Sleep/Restart/Power Off and, for Restart/Power Off, quits RetroArch (SRAM written) before replying (quit timeout 10 s, then SIGTERM, then SIGKILL of the process group). The CLI gives up after 25 s.
- Home: `library.rs` `launch_game` / `start_game_listener` (`GAME_RUNNING`); `on_game_session` stops Home Music while a game runs and restarts it after.
- Closing screen (user request 2026-10-15, "una schermata analoga a quella di splash di avvio per quando il gioco si sta chiudendo"): Home's loading screen sits UNDER RetroArch, so the closing one is drawn by the Quick Menu over the game: passive full-screen surface `SurfaceKind::Closing` (surface-mode 3, `closing-view` in quick_menu.slint, same layout as Home's `launch-view`, string 1286 "Closing game…"), no input capture (the Quick Menu/power keys do not open the menu meanwhile). emud snapshot `quitting=1` from the moment a quit is asked (the rotation-slot save before the quit still runs with `state=running`) until idle; not for the netplay host relaunch. The QM fetches title, system name, system colour (libraryd `DETAILS` + `STATUS`) and decodes the cover (rounded corners in Rust: an image is not clipped by a rounded parent) as soon as a game runs, so the screen is complete at once; dropped at session end. Checked on the CubeXX 720x720 (Gran Turismo 2: closing screen during the save, then Home). ui-shot `qm_game_closing`, `qm_game_closing_nocover` (QM scenes: run without ONLY). Home keeps its inputd UI capture: inputd routing ignores it while gamepads are on.

## Game UX: Details, per-game settings, screenshots, BIOS, metadata, achievements (§37.18)
- libraryd: `DETAILS\t<game>` (game line + `system_name= sessions= path= size= added=`, `member=<cid>\t<name>\t0|1` per collection, `meta_<key>=` from `/userdata/library/metadata/<system>/<rom stem>.txt`), `STATS_RESET\t<game>|all`, `DELETE\t<game>\tCONFIRM` (ROM + files its .m3u/.cue own, two levels, not ones another available game references; cover in the covers store and metadata removed; saves/history kept; `ERR busy` for the game in session; main file last). CLI: `nuubos-libraryctl details|hide|stats-reset|delete GAME confirm`. Host test `python3 package/nuubos/nuubos-library/tests/details-delete.py`.
- emud per-game overrides: `GAME_SETTINGS\t<game>\t<system>` → `core= core_default= core_override= cores=a,b aspect= filter= filter_default=crt|sharp end=1` (filter_default = what an empty filter gives: `crt` for a `crt` system with the user's CRT Effect on; the Video Filter row shows "Default (CRT Effect)"); `GAME_SET\t<game>\t<system>\t core|aspect|filter\t<value or empty>` (aspect core|4:3|16:9|full|integer, filter sharp|smooth|pixel, core must be an available core of the system); `GAME_RESET\t<game>`. Stored only as overrides in `/userdata/users/<id>/appdata/nuubos-emulation/games/<game>.conf` (so Reset User Profile clears them). Applied at launch in the session config; keys a session overrides (aspect/scale/shader/smooth/cheevos_*) are snapshotted from the user's retroarch.cfg and restored when RetroArch exits (RetroArch saves its config on exit). Emud roots are `#ifndef` overridable; host test `python3 package/nuubos/nuubos-emulation/tests/game-settings.py` (real libraryd + emud + fake RetroArch).
- Screenshots: emud `SCREENSHOT` (RetroArch stdin `SCREENSHOT`, RetroArch's own rendering) confirmed by inotify on the user's screenshot dir (new `.png` closed within 5 s) → `game.screenshot.saved|failed`. Hotkey M+L2 (inputd `screenshot`), QM GAME row 18 (between RetroArch Advanced and Quit Game; geometry 6 steps, Quit moved to 7).
- RetroAchievements: `nuubos-achievementsctl status|login USER NAME (password stdin)|logout|set USER enabled|hardcore 0|1` (libcurl, rcheevos `login2` endpoint; only the token is stored, `/state/users/<id>/secrets/retroachievements.conf` 0600). Emud writes `cheevos_*` into the session config for that user and removes the token from the user's USERDATA config afterwards. Not done: achievement unlocks as nuubOS notifications (RetroArch shows its own popups) — needs RetroArch log/stdout integration.
- Hardcore Mode (user request 2026-10-11): a hardcore session (`ENABLED=1` + token + `HARDCORE=1`, read at launch) has no save states at all. emud: STATUS `hardcore=1`; `SAVE_STATE`/`LOAD_STATE`/`SLOT`/`FAST_FORWARD` and the hotkeys save/load/slot ± /fast-forward → `ERR hardcore` + notification `game.hardcore` (QM toast "Not available in Hardcore Mode", i18n 910); the game always starts from the beginning (`resume` ignores states, `slot:N` → `ERR hardcore`), no auto save/load and no rotation save at quit or PRE_POWER (only SRAM, written by the quit). `STATES` answers `hardcore=1` without states: Home's Start Game sheet shows only Start from the Beginning + "Save states are off in Hardcore Mode" (911). QM hides Save State / Load State / State Slot (`game-hardcore`, `game-states` row offset). Turning it on (Settings page 54 and web admin) first shows a confirmation dialog explaining it (907-909; Home `settings-dialog-*`, generic M3 dialog, `gameui::dialog_action`; closed when Settings closes). Host test `game-settings.py` covers emud; ui-shot scenes `achievements_hardcore`, `start_game_hardcore`, `qm_game_hardcore*`. Not hardware-qualified.
- BIOS Manager: `nuubos-biosctl status [SYSTEM]` (shell): per cores.conf system, firmware of the effective core's libretro core-info (MD5 from the core-info notes, MIT), filtered/overridden by the curated `/usr/share/nuubos/emulation/bios.conf` (`system|required|any|optional|none|files`); MAME machine systems need `mame/bios/<machine>.zip`. States ready/missing/invalid/optional; files ok/missing/invalid/unverified. nuubOS never ships firmware. Fixed process count whatever the number of systems (2026-10-08; the per-system/per-file awk+md5sum forks took ~3 s on a desktop, much more on H700): one awk builds the plan, shell builtins test existence, one md5sum for present files with a reference, one awk derives states; output byte-identical to the old script (checked on GNU and BusyBox). UI page 52: YOUR SYSTEMS (libraryd snapshot systems with ≥1 game, `library::system_ids()`) then OTHER SYSTEMS (`gen-split`); the count detail only on missing/invalid systems.
- Scraper (rework 2026-10-09, user decisions: alternative sources + Skyscraper as backend only): package `nuubos-scraper` (`nuubos-scraper game GAME [force|fill]|bulk all|missing|system:ID|search GAME (name on stdin)|accept|reject|clear GAME|provider status|set screenscraper|thegamesdb|libretro|account status|set NAME|clear|apikey set|clear`, libcurl) is the service contract; the UI never runs Skyscraper. Sources (device-wide `/state/scraper/scraper.conf` `PROVIDER=`, default screenscraper when Skyscraper is installed): **screenscraper/thegamesdb through Skyscraper** (package `thirdparty/skyscraper`, Gemba fork 3.21.0, GPL-3.0+, built with our own `CMakeLists.txt` because Buildroot's Qt6 has no qmake; needs qt6base GUI/NETWORK/SQL/XML/PNG/JPEG, which needs pcre2 with 16-bit: after enabling Qt6 `pcre2-reconfigure` was required). Skyscraper brings its own registered ScreenScraper devid and TheGamesDB key, so nuubOS needs no developer credentials (verified 2026-10-09: the API answers 403 without a devid; our own C code must never reuse Skyscraper's credentials). Run model (`sky_lookup`): HOME=`/run/nuubos/scraper` (tmpfs, 0700) with `.skyscraper/config.ini` (0600: cacheFolder `/userdata/library/cache/skyscraper`, unattend, spaceCheck off, no videos/wheels/marquees/textures, brackets off, maxLength 4000, lang = user language, `[screenscraper] userCreds` from `/state/scraper/screenscraper.conf`, `[thegamesdb] userCreds` from `/state/scraper/thegamesdb.conf`) and an `artwork.xml` with raw `cover` (720 high) and `screenshot` (640 wide) outputs; gather `Skyscraper -p <sky platform> -s <module> -i /userdata/roms --flags unattend,nowheels,nomarquees,notextures --addext '*.ext' FILE` (bulk: `--includefrom`, one run per system; search name: `--query` with '+' for spaces, single file), then generate `-f pegasus -g <scratch> -o <scratch>/media --flags unattend,nobrackets` into `/userdata/library/cache/skyscraper-out/<pid>` (same FS as the store) and parse `metadata.pegasus.txt` (`game:`, `file:`, `rating: 90%`, `release: yyyy-MM-dd`, multi-line values indented, `  .` = empty line, `assets.boxFront`, `assets.screenshot`).
